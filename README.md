## 项目简介

SMART-M 是一套面向**工业电机运行状态监测**的嵌入式智能终端系统。系统以 STM32F407VET6 为主控，运行 FreeRTOS 实时操作系统，通过温湿度、六轴姿态、电源电流等多类传感器实时采集电机运行参数，在边缘端完成振动特征提取与故障诊断，实现**过热 / 过载 / 异常振动 / 不平衡 / 轴承故障**的自动识别与告警联动（继电器断电保护 + 蜂鸣器报警），并借助 ESP8266 通过 MQTT 协议将数据上报至**华为云 IoTDA** 平台，支持远程监控与命令下发；同时支持 **DX-BT24 蓝牙透传**（微信小程序本地监控）与 **SD 卡数据落盘**（本地 CSV 记录）。

系统采用 **`01_app / 02_svc / 03_plat / 04_bsp / 05_common` 五层软件架构**，按"应用 — 服务 — 平台 — 板级 — 公共"逐层解耦，全部模块由条件编译开关统一管控，可按实际硬件裁剪固件，代码可读性与可维护性兼顾。

## 功能特性

### 传感器采集（共享 I2C 总线）
| 传感器 | 型号 | 功能 |
|---|---|---|
| 温湿度 | SHT30 | 环境温湿度采集（共享软件 I2C 总线，地址 0x44） |
| 六轴姿态 | QMI8658 | 三轴加速度 + 三轴陀螺仪，振动/姿态数据源（共享软件 I2C 总线，地址 0x6B） |
| 电源监测 | INA226 | 母线电压 / 电流 / 功率监测，过流自动断电保护（共享软件 I2C 总线，地址 0x40，采样电阻 0.01Ω R010） |

> SHT30 / QMI8658 / INA226 三个传感器统一挂在**共享软件 I2C 总线（PB6=SCL / PB7=SDA）**上，各器件地址不同（0x44 / 0x6B / 0x40），互不冲突；驱动内置**总线恢复机制**（9 个 SCL 时钟脉冲 + 停止位），可释放被从机异常拉低的 SDA，防止总线死锁。

### 边缘智能
- **振动特征提取**：1 秒滑动窗口，计算 RMS / 峰值 / 峭度 / 峰值因子；
- **故障诊断规则引擎**：输出 `正常 / 注意 / 异常` 三级状态，并生成 `过热 / 过载 / 振动异常 / 不平衡 / 轴承` 故障位图；
- **滑动平均滤波**：10 点窗口，传感器数据去抖。

### 告警联动与安全保护
- 三路独立告警阈值：**温度（℃）/ 振动（g）/ 电流（A）**；
- 迟滞恢复机制，防止阈值边界抖动误报；
- 过流 / 超限自动断开**继电器**（串接电机电源回路）并驱动**蜂鸣器**报警；
- 阈值可通过 4×4 矩阵键盘现场调整，并持久化到 STM32 **内部 Flash**（Sector11），重启不丢失。

### 云平台接入（WiFi + MQTT）
- **ESP8266 + Paho MQTT Embedded C** 连接华为云 IoTDA（非加密 1883 端口，IPv4 直连）；
- 按**华为云物模型** JSON 格式周期上报属性（温度 / 湿度 / 六轴 / 电压电流功率 / 继电器 / 告警 / 诊断）；
- 订阅云端下行命令：**LED_Control**（`led` 与 `led_index+state` 双模式）、**RELAY_Control** 继电器远程控制，并回传命令响应；
- **断网补传**：断网期间数据缓存（RAM 16 条 × 256B），重连后 FIFO 批量补发，不丢数据；
- **全链路断线自动重连**：指数退避（1s → 30s 封顶），连续 5 次失败自动复位 ESP8266 模块；
- **WiFi 断线感知（三态）**：异步检测 `WIFI DISCONNECT` 事件、`AT+CIPSTATUS` 二次确认真实在线、断线立即重连；CIPSTATUS 查询失败时信任 GetIP 结果，避免 AT 瞬时无响应造成反复重连。

### 蓝牙透传（DX-BT24 BLE）
- **USART2（PA2/PA3）9600bps** 连接 DX-BT24 BLE 透传模块；
- 连接后**周期上报传感器快照 JSON**（一行一帧），经 BLE 通道发给微信小程序；
- 解析小程序下行命令：**QUERY / RELAY / LED / PING / BEEP**，并回传应答；
- 与 MQTT 共用业务入口，云端 / 本地双通道监控。

### SD 卡数据存储（FatFs）
- **SDIO 4bit**（PC8-PC12 + PD2）连接 TF 卡，FatFs 文件系统；
- 每 5s 将诊断快照（温度/湿度/振动/电流/电压/功率/告警）追加写入 `/SMART/LOGxxxx.CSV`，单文件上限 256KB 自动滚动新建；
- 提供 `APP_SD_AppendLine()` 供其他任务写入事件行（告警 / 状态等）。

### 人机交互
- **4×4 矩阵键盘**：页面切换、继电器控制、蜂鸣器测试、告警阈值设置；
- **OLED（SSD1306）**：实时数据 / 阈值配置 / 系统状态三页面显示，告警时闪烁提示。

## v4.0 更新内容

### 1. 引脚与连接方式进阶（硬件层重构）
- **三传感器统一共享 I2C 总线**：SHT30 / QMI8658 / INA226 全部挂到 `bsp_i2c_soft` 共享软件 I2C 总线（**PB6=SCL / PB7=SDA**，原各器件独立/分挂 PB8/PB9 方案），简化接线、统一时序；
- **INA226 换新模块**：改用蓝色 R010 款（A0/A1 出厂接 GND → 地址 **0x40**，原 0.45；采样电阻 **0.01Ω**，原 0.1Ω），驱动同步更新；
- **I2C 总线恢复机制**：初始化/异常时自动产生 9 个 SCL 时钟脉冲 + 停止位，释放被从机拉低的 SDA，防总线死锁；
- OLED 保留**独立总线2（PD6/PD7）**，与传感器隔离，互不干扰。

### 2. 新增 DX-BT24 蓝牙透传（本地无线监控）
- 板级：`bsp_bt24`（USART2/PA2-PA3，9600bps，DMA 环形接收 + IDLE 判帧）；
- 应用：`app_bt24`（BT24Task）——连接后周期上报传感器快照 JSON（一行一帧），解析小程序下行命令 **QUERY / RELAY / LED / PING / BEEP** 并应答；
- 模块开关：`BSP_BT24_ENABLE` / `APP_BT24_ENABLE`。

### 3. 新增 SD 卡数据存储（本地数据落盘）
- 板级：`bsp_sd`（SDIO 4bit：PC8-PC12 + PD2，FatFs diskio）；
- 应用：`app_sd`（SD 任务）——上电挂载 FAT 文件系统，每 5s 追加写入诊断快照 CSV（`/SMART/LOGxxxx.CSV`，256KB 滚动），支持其他任务事件行写入；
- 模块开关：`BSP_SD_ENABLE` / `APP_SD_ENABLE`。

### 4. WiFi 断线感知升级：三态检测
- `BSP_ESP8266_IsWiFiConnected()` 由二值改为**三态**：`1`=在线 / `0`=确切断线（STATUS:5）/ `-1`=查询失败（AT 瞬时无响应）；
- `app_mqtt.c` 连接阶段：查询失败时**信任 GetIP 结果跳过 rejoin**，避免 AT 瞬时无响应导致的 2~10s 反复重连；确切断线（STATUS:5）仍走立即重连；
- 异步 `WIFI DISCONNECT` 事件检测与断线立即重连逻辑保持不变。

### 5. 串口调试过滤
- 新增 `BSP_UART1_SD_ONLY`（1=只输出 [SD] 打印，调 SD 卡用）、`APP_BT24_UART1_PRINTF_ENABLE`（BT24 任务打印开关）。

## v3.0 更新内容

### 1. 平台层（03_plat）框架落地
`03_plat` 从预留目录升级为**对象化平台框架**，随 v3.0 正式实现：

| 模块 | 文件 | 职责 |
|---|---|---|
| 对象模型 | `plat_obj.h / plat_obj.c` | 平台对象抽象与生命周期管理 |
| 设备管理器 | `plat_devmgr.c` | 设备对象注册、查询与统一管理 |
| 服务管理器 | `plat_svcmgr.c` | 平台服务注册与调度 |
| 连接器抽象 | `plat_conn.h / plat_conn.c` | 连接器接口抽象，MQTT 连接状态经 `app_conn_engine` 注册为连接器，由 `PlatSvcTask` 周期驱动刷新 |
| 板级管理 | `plat_brd.h / plat_brd.c / plat_brdmgr.c` | 板级资源统一管理 |
| OLED 对象化 | `plat_oled.h / plat_oled.c` | OLED 显示设备对象化封装 |

### 2. WiFi 断线感知精进
- **异步断线事件检测**：`BSP_ESP8266` 在接收泵（`pump_rx`）中实时监听模块上报的 `WIFI DISCONNECT` / `WIFI CONNECT FAIL` 异步事件并置位 `s_wifi_closed` 标志，业务层无需轮询即可感知热点断开；
- **防"假在线"**：连接阶段 `GetIP` 成功后再用 `AT+CIPSTATUS` 二次确认 WiFi 真实在线——解决热点断开后 `CIFSR` 仍返回旧 IP 导致误判在线的隐患，确认假在线后自动重新 `JoinAP`；
- **断线立即重连**：MQTT 主循环在 `MQTTYield` 前检查异步断线标志，一旦触发立即关闭 TCP 并走**指数退避重连**（不等 10s TCP 保活探测，恢复更快）；
- **新增 BSP 接口**：`BSP_ESP8266_IsWiFiConnected()`（CIPSTATUS 查询）、`BSP_ESP8266_IsWiFiClosed()`（异步事件标志查询）、`BSP_ESP8266_ClearWiFiClosedFlag()`（清除标志）。

## v2.0 更新内容

### 1. 软件架构升级：四层 → 五层
原 `APP / Protocol / BSP / Common` 四层重构为五层，业务职责进一步分离：

| 层级 | 目录 | 职责 |
|---|---|---|
| **应用层** | `01_app` | FreeRTOS 任务、业务入口、通信协议（含 `protocol/` 子目录） |
| **服务层** | `02_svc` | 告警、诊断、故障、配置、传感器快照、继电器、离线补传、滤波、振动特征 |
| **平台层** | `03_plat` | 对象化平台框架（见 v3.0） |
| **板级层** | `04_bsp` | 外设驱动：传感器、显示、键盘、ESP8266、Flash 存储等 |
| **公共层** | `05_common` | 环形缓冲、通用工具、**模块条件编译开关** |

### 2. WiFi / MQTT 上云精进
- **IPv4 直连 IP**（`MQTT_BROKER_IP`）：华为云接入域名同时存在 IPv6（AAAA）记录，ESP8266 AT 固件解析 IPv6 会超时，导致"WiFi 已连上但 TCP connect 一直失败"。v2.0 通过解析出的 IPv4 A 记录直连，实测彻底消除该问题；
- **指数退避重连**：重连间隔 1s 起步、30s 封顶，避免断线风暴；
- **连续失败复位**：重连连续失败 5 次，自动发送 `AT+RST` 复位 ESP8266 模块；
- **TCP 保活看门狗**：10s 检测一次 TCP 连接状态，异常时强制关闭并重建 TCP；
- **MQTT 专用收发模式**：`BSP_ESP8266_EnterMQTTMode() / TCPRead()`，二进制安全，不再追加 `\n`；
- **线程安全发布接口**：`APP_MQTT_Publish() / APP_MQTT_PublishTopic()`，其他任务（采集 / 告警 / 影子上报等）可随时安全上报，失败自动转离线缓存；
- **下行命令增强**：LED_Control 支持两种参数格式，新增 RELAY_Control 继电器远程控制；
- **属性上报扩展**：SHT30 / QMI8658 / INA226 / 继电器 / 告警 / 诊断状态统一经传感器快照上报；
- **设备消息队列**：新增 `sys/messages/up` 发布与 `sys/messages/down` 订阅主题；
- **串口日志任务**：新增独立日志输出任务，与业务解耦。

| **平台层** | `usrcode/03_plat` | 对象化平台框架（对象模型 / 设备·服务管理器 / 连接器抽象 / 板级管理 / OLED 对象化） | `plat_obj` `plat_devmgr` `plat_svcmgr` `plat_conn` `plat_brdmgr` `plat_oled` |
| **板级层** | `usrcode/04_bsp` | 外设驱动 | `bsp_i2c_soft` `bsp_sht30` `bsp_qmi8658` `bsp_ina226` `bsp_esp8266` `bsp_bt24` `bsp_sd` `bsp_oled` `bsp_key_matrix` 等 |
| **公共层** | `usrcode/05_common` | 公共组件与全局开关 | `ring_buffer` `common` **`module_cfg`** |

**模块裁剪**：所有模块在 [`usrcode/05_common/Inc/module_cfg.h`](usrcode/05_common/Inc/module_cfg.h) 中通过 `#define XXX_ENABLE 1/0` 统一管控，禁用模块不参与编译，节省 Flash 与 RAM；模块间依赖关系在编译期通过 `#error` 强制检查。

**分层依赖规则**：`01_app → 02_svc → 03_plat → 04_bsp → 05_common`，上层调用下层接口，下层不反向依赖上层。

## FreeRTOS 任务

| 任务 | 周期 | 说明 |
|---|---|---|
| `SHT30 采集` | 周期 | 温湿度采集 → 写入共享快照（共享 I2C 总线） |
| `QMI8658 采集` | 周期 | 六轴数据采集 + 姿态解算 → 共享快照 |
| `INA226 监测` | 周期 | 电压/电流/功率采集，过流自动断电保护 |
| `振动特征提取` | 1s 窗口 | RMS / 峰值 / 峭度 / 峰值因子 |
| `故障诊断` | — | 规则引擎，输出健康状态与故障位图 |
| `告警联动` | — | 三路阈值比较 + 继电器断电 + 蜂鸣器 |
| `MQTT 上云` | 3s 上报 | ESP8266 联网（IPv4 直连 + 退避重连 + 三态断线感知），Paho MQTT 上报/下行命令处理 |
| `断网补传` | — | 断网数据缓存（RAM 16 条），重连批量补发 |
| `PlatSvcTask` | 周期 | 平台服务调度，周期驱动 MQTT 连接器状态刷新 |
| `BT24Task` | — | 蓝牙透传：周期上报快照 JSON + 解析小程序命令（QUERY/RELAY/LED/PING/BEEP） |
| `SD 存储` | 5s | FatFs 挂载 + 诊断快照 CSV 落盘（256KB 滚动） |
| `矩阵键盘` | — | 消抖 + 页面切换 / 继电器 / 阈值设置 |
| `OLED 显示` | — | 实时 / 阈值 / 状态三页面 + 告警闪烁 |
| `串口日志` | — | 独立日志输出任务 |

任务统一在 [`usrcode/01_app/Src/app_tasks.c`](usrcode/01_app/Src/app_tasks.c) 创建（与 CubeMX 生成的 `freertos.c` 保持隔离），集成点位于 `main.c` 与 `freertos.c` 的 USER CODE 区域。

## 快速上手

1. **云端准备**：按 [`华为云IoTDA配置指南.md`](华为云IoTDA配置指南.md) 开通华为云 IoTDA（免费单元即可），创建产品（MQTT + JSON）、定义物模型服务（`Sensor`：`temperature` / `humidity` 属性，`LED_Control` / `RELAY_Control` 命令）、注册设备；
2. **修改配置**：将 [`usrcode/01_app/Inc/app_mqtt.h`](usrcode/01_app/Inc/app_mqtt.h) 中 WiFi 名称/密码、华为云 `clientId / username / password`、设备 ID 替换为你的实际参数（可用华为云在线鉴权工具生成；`MQTT_BROKER_IP` 可留默认，若域名解析正常也可改用域名接入）；
3. **编译烧录**：按上文构建流程生成固件并烧录；
4. **验证**：上电后 ESP8266 自动连网 → MQTT 连接 → 周期上报属性；在华为云控制台可看到实时数据，下发 `LED_Control` / `RELAY_Control` 命令可远程控制板载 LED / 继电器；
5. **蓝牙调试**：手机打开微信小程序连接 DX-BT24，接收实时遥测 JSON，可下发 QUERY / RELAY / LED / PING / BEEP 命令；
6. **SD 记录**：插入 TF 卡后上电，自动挂载 FatFs 并每 5s 写入 `/SMART/LOGxxxx.CSV`；
7. **断网测试**：断开 WiFi，模块异步上报 `WIFI DISCONNECT`，终端立即走退避重连；数据缓存于 RAM，恢复后自动补发全部缓存数据；多次失败自动复位 WiFi 模块。

> ⚠️ 示例中的云端参数为开发阶段实测值，正式部署请务必替换为你自己的设备凭据。
