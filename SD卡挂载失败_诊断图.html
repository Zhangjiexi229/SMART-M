STM32F407 SD 卡挂载失败 — 诊断

SMART-M 项目 · 串口日志（XCOM V2.6）· 2026-09-14
结论：不是卡坏、也不是 FAT32 格式问题。挂载失败（fr=1 = FR_DISK_ERR）的根因是工程对 HAL 驱动做了改动：SDIO 数据阶段硬件超时被设为 DataTimeOut = 0x40（注释声称 0.5s，实际在 400kHz 时钟下只有 160µs），远小于 SD 卡读扇区的访问时间（通常几 ms），导致每次读扇区 0 都触发 err=8（DATA_TIMEOUT），挂载永远失败。
① 现象（日志证据）

串口日志里发生了什么

日志逐行对应代码：app_sd.c / bsp_sd.c / stm32f4xx_hal_sd.c
[SD] card ok: 1146 MB
卡片识别成功，但容量是 误报：真实容量 61,067,264 扇区 × 512B ≈ 29.1 GiB（32GB 卡），bsp_sd.c 用 uint32 算容量发生溢出才打印出 1146 MB。
[SD] rd blk=0 err=8 sta=0
读 0 号扇区失败，err=8 = HAL_SD_ERROR_DATA_TIMEOUT：卡接收了 CMD17 命令，但数据阶段超时、一字节数据都没收到。
[SD] mount fr=1 t=12 ms
f_mount 返回 fr=1 = FR_DISK_ERR（底层磁盘读写错误），不是 FR_NO_FILESYSTEM(13)，所以与 FAT32 格式无关。
[SD] not ready, retrying...
每 30s 重复一次挂载尝试，全部同样失败；提示语 “check card & FAT32” 对 fr=1 属于误导。
② 根因（机制链）

为什么识别成功、读扇区却必超时

SDIO 初始化成功（CMD0→CMD8→ACMD41→CMD2→CMD3→CMD7）：命令阶段全部通过。
↓
容量/CSD 能读出：CMD9/CMD10 的 CID/CSD 是命令响应（R2 寄存器）返回，不走数据总线 —— 所以看起来“卡没问题”。
↓
FatFs 挂载时真正读扇区（CMD17），数据必须走 D0 数据线，受 DTIMER（数据超时计数器）约束。
↓
工程修改：HAL_SD_ReadBlocks/WriteBlocks 共 8 处把 config.DataTimeOut 设为 0x40U，注释写 “0.5s@400kHz”。
↓
0x40 = 64 个 SDIO_CK 周期 @ 400kHz = 160µs（真正 0.5s 需要 200,000 周期 = 0x30D40），比声称值小约 3125 倍。
↓
SD 卡读单块访问时间 tAC 通常为几 ms > 160µs → 数据还没开始发，DTIMER 已到期 → DTIMEOUT(8) → fr=1 → 挂载失败。
超时值换算：DataTimeOut 是 24 位计数器，按 SDIO_CK 时钟计数。
现在：0x40 = 64 周期 → 64 ÷ 400,000Hz = 160µs（任何读都会超时）
应为：0.5s → 200,000 周期 = 0x30D40（注释本来的意图）
稳妥方案：0xFFFFFF（24 位最大值） → 400kHz 下 ≈ 41.9s，24MHz 下 ≈ 699ms，兼容后续提速。
数据阶段允许等待时间对比（对数刻度示意）
160µs
当前 0x40 几 ms
卡读扇区 tAC 0.5s
原注释意图 实际超时点 → 卡来不及响应 建议起点 0xFFFFFF
超时区（必失败）风险区安全区
③ 修复方案

三步解决

1. 改超时（根因，8 处）：stm32f4xx_hal_sd.c 中 8 处
config.DataTimeOut = 0x40U; → config.DataTimeOut = 0xFFFFFFU;
（若想保留“有界超时”防看门狗饿死，可按当时 SDIO_CK 频率换算：400kHz→0x30D40；提速到 24MHz 后必须重算，0x40 会只剩 2.7µs，更糟。）
2. 修容量打印（次要）：bsp_sd.c 的 capacity_bytes = BlockNbr * BlockSize 用 uint32 会溢出，32GB 卡被误报成 1146 MB。
改为先除后乘或 64 位计算，例如 (uint32_t)((uint64_t)BlockNbr * BlockSize / 1048576) 后打印 MB。
3. 若改完仍失败，再查硬件：板上 SDIO 无外部上拉（靠内部弱上拉），按可靠性顺序检查 —— D0/CMD 加 10kΩ 上拉到 3.3V → 卡 VDD 就近加 10µF+100nF 去耦、供电线加粗 → 线序/接触（PC8=D0, PD2=CMD, PC12=CK） → 换一张已知良好的卡交叉验证。
另注意：FreeRTOS 空闲堆在 SD 任务启动时仅 8168B，偏紧但不影响本次挂载；后续若要长期写日志建议评估堆水位。
